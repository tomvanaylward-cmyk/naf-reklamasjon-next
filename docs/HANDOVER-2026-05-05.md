## 6. Arbeidsmåte og mønstre

- **Subagent-driven development** for multi-task implementasjon (superpowers:subagent-driven-development)
- **Brainstorming → spec → plan → implementasjon** for nye pakker
- **Specs i** `docs/superpowers/specs/`, **planer i** `docs/superpowers/plans/`
- **DB-migrasjoner** legges i `docs/migrations/` som idempotente SQL-filer. Brukeren kjører dem manuelt i Supabase SQL Editor (vi har ikke automatisert migrasjonskjøring)
- **Audit-mønster:** systemhendelser logges som interne `messages` på saken med `sender_name: '🔁 System'`
- **Mutasjon som krever RLS-bypass:** rute gjennom `/api/*`-endepunkt med service-role-klient (`adminDb` fra `lib/admin-api.ts`)
- **Brukerverifisering ved tvil:** brukeren foretrekker korte, ærlige tilbakemeldinger. Foreslå 2–3 alternativer med pros/cons, gi anbefaling, vent på «kjør»
- **Commit-stil:** norsk, conventional-commit-prefiks. Co-Authored-By Claude
- **Brukerens repo-feilfunksjon:** han glemmer ofte å `cd naf-reklamasjon-next` — bruk alltid absolutte stier eller `cd` eksplisitt i Bash-kall
